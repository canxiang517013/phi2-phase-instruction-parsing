# P0-2 实验记录深度分析：从结果反推代码与设计根因

日期：2026-10-12　|　输入：`results_v2/` 全部逐条记录（600 条 × 5 档）+ `dataset_phased_v5.jsonl` 训练分布
方法：解剖脚本 `evaluation/p0_deep_dive.py`（Q1-Q7 逐项取证）+ 训练集边际统计
定位：每个发现 = 现象（数据证据）→ 根因（代码/数据/设计层）→ v6/P0-4 修复建议

---

## 发现一：z 轴是全部软肋的汇聚点——它是"相位身份"的载体

**现象**（Q1，v5-Q8_0 phase 200 条）：

| 相位 | 正确 | z 期望→实际分布 |
|---|---|---|
| ASSEMBLE (z=5) | 23/40 | z5→z5 ×21；**z5→z15 ×8**（窜到 RECON/OBST 的 z）；z5→z25 ×3 |
| HOLD (z 自由 6-10) | **40/40** | 全对，无窜扰 |
| OBSTACLE (z=15) | 21/40 | z15→z15 ×21；失败散布 z8/z17/z22/z20 |
| RECON (z=15) | 31/40 | z15→z15 ×31；**z15→z5 ×9** |
| RECONFIGURE (z=8) | **0/40** | **z8→z15 ×39, z8→z5 ×1（单向殖民）** |

phase 失败中 z 相关占 ~78/95；错误类型分布（Q8: target-z=79 主导）由此而来。

**根因（设计层）**：`gen_testset.py`/v5 训练规则把 z 设计为相位指纹——ASSEMBLE z=5、OBST/RECON z=15、RECONFIGURE z=8、HOLD 自由。模型推断 z 实质是推断相位身份。HOLD 满分（z 有真实自由度且与 5/15 分离）、RECONFIGURE 零分（**target 恒 (15,15,8)，全相位唯一无数值自由度的设计**——身份信息只能挤在 z 一个槽里，而 z=15 是训练集最高频值（78 次 vs z=5 72 次 vs z=8 57 次），低边际竞争必然塌向众数）。

**修复**：v6 把 z 从身份载荷中剥离——RECONFIGURE 的 mark point 参数化（如 `RECONFIGURE@line@(15,15,8)`）或给各相位 z 加受控扰动增强；9 月已知此问题（"v6 重训首要修复目标"），本分析给出了机理证据。

## 发现二："FP16 不优于 Q8"的机制 = z 边界上的硬币翻转

**现象**（Q7）：FP16 与 Q8_0 在 phase 上的 17 条分歧**全部是 target-z**，且方向一致（期望 z=15 → 输出 z=5，即 RECON→ASSEMBLE 窜扰）。分散于 seen 6 / in-range-unseen 4 / ood 7。

**根因**：z 身份决策是低边际（low-margin）判断，量化噪声与 dtype 噪声都恰好能翻转它；哪一档"翻对得多"是抽签。这解释了为什么 8 月 16 条上 Q8 88%<Q6/Q5 100%（小样本 + 硬币），也解释 600 条上 FP16 52.5% ≤ Q8 57.5%。"选更高位档位提升相位能力"是错觉——**修 z 设计比选档位重要**；z 修复后档位排序可能重排（P0-2 主表须重测）。

## 发现三：越界回声 100% 精确、零钳制——transcriber 是被训练出来的技能

**现象**（Q4a）：23/23 危险输出全部**逐位精确回声**指令坐标（z=350、z=-28、y=807 原样转写），无一裁剪、无一向训练盒收缩。Q3 佐证：ood 相位参数 63/64 直传、**0 条钳回训练盒**。

**根因（数据层）**：v5 训练样本的 target 永远 = 指令中坐标的复制——模型学到的核心技能就是"转写数字"。训练分布不存在任何拒绝/裁剪样本，包络概念在**设计层缺失**，不是模型"变坏"。

**修复决策**：两条路线——(a) 外置确定性安全层（P0-4 既定方案）：模型行为可预测（精确回声），外置层一条规则即可拦截，简单可靠；(b) v6 内化安全（训练加越界→拒绝/裁剪样本）。P0-2 证据**支持 a 为主**：模型可预测性高（见发现四），且内化安全引入新的训练目标会进一步挤占容量（P0-3 G7 已证预算敏感）。

## 发现四：缺字段捏造 = 训练分布逐维众数吸引子 (15,15,15)

**现象**（Q4b）：15 条 no-coords 全部输出 target=(15,15,15)——**无一随机**。10 条 no-uav-id 输出 ids=[1]（单机模板）或 [1,2,3]（编队模板）同样是模板先验。

**根因（机制层，已定量证实）**：训练集坐标边际众数 x=15（53 次）、y=15（51 次）、z=15（78 次）——(15,15,15) 是 next-token 统计的逐维众数，RECONFIGURE 的固定 (15,15) 与 RECON/OBST 的固定 z=15 共同塑造。缺输入时模型输出分布回落到先验众数。

**工程含义**：缺字段行为**完全可预测** → 安全层可写针对性规则（如 target==(15,15,15) 视为缺输入指纹，要求上游重发——需防过拟合，v6 后重测）；同时说明"模型从不拒绝"不是 bug 而是 SFT 目标的定义——没有 REFUSE token 可学。

## 发现五：mode 字段冗余 → 低位档位下的字段串槽

**现象**（Q2）：Q5_K_M basic 仅有的 4 条 mode 失败，全部是 `mode='line'/'grid'`——**formation 值占用了 mode 槽**；ids 与 target 全对。仅出现在 Q5/Q4（Q8/Q6 零失败）。

**根因（schema 设计层）**：mode ∈ {single-agent, swarm} 与 len(uav_ids) 完全冗余相关；formation 与 mode 语义相邻。低比特噪声下相邻槽位互窜。**冗余字段 = 噪声敏感点**。

**修复**：v6 schema 二选一——删 mode（下游由 ids 推导）或输出顺序调整（ids/formation/target 在前，mode 靠后降低互窜概率）；评测器字段级准确率（P0-2 新增指标）正是为此类问题设计的监控点。

## 发现六：长态势崩溃 = 显著数字捕获，不是格式崩溃

**现象**（Q5）：长态势失败输出常是 schema 合法 JSON，坐标却抄自态势文本的显著大数（153/160 = 态势里的侦察区/航点坐标），指令尾部的真实坐标被忽略（R-016 偶然正确）。P0-3 已证：同长结构化摘要同样崩溃（9-12%）、加 120 条长样本可修到 57%。

**根因**：训练分布中"大坐标"几乎只以"待转写目标"身份出现（RECON 62-240），长上下文中出现的大数被默认为目标——分布外注意/抽取失败，非 JSON 能力失败。

## 发现七：随机相位 29/30 精确跟随、零钳制——规则已泛化，x/y 无记忆盒

**现象**（Q6）：跨域随机参数（ASSEMBLE@(-200,150) 等）x/y 映射 29/30 精确（±5 容差），0 条收缩回训练盒。结合 P0-3 G5（63-70% 总正确）与发现一：剩余失败全部是 z。

**含义**：模型学到的是**映射规则**而非坐标记忆——x/y 的 phase 条件化是真泛化。这把创新点 1 的证据从"能跑"升级到"学到了规则"；同时也意味着 G5 的正确解读是"z 未泛化，x/y 已泛化"。

## 发现八：盒内未见 < 盒外的反直觉 = 三种机制并存

**现象**（Q3，Q8_0）：seen 80% > ood 73% > in-range-unseen 57%。

**机理分解**：seen = 记忆化映射（label 与 target 联合记忆）；ood = 极端大数触发"直传转写"（与 RECON 训练行为同构，63/64 直传）；in-range-unseen = 参数可信地落在训练值附近但未见过，必须真正内插规则——最难路径。三种机制叠加造成非单调排序，**不能解读为"越极端越好"**。

## 汇总：设计层修复清单（v6 / P0-4 输入）

| # | 问题 | 层 | 修复 | 优先级 |
|---|---|---|---|---|
| 1 | z 作为相位身份载体、RECONFIGURE 无数值自由度 | 数据设计 | z 参数化/扰动增强；RECONFIGURE 加数值自由度 | 高（决定 phase 上限） |
| 2 | 越界/歧义无拒绝路径 | 系统设计 | 外置确定性安全层（P0-4），不内化训练 | 高 |
| 3 | mode 冗余字段 | schema | 删 mode 或调整字段顺序 | 中 |
| 4 | 缺字段→众数吸引子 | 数据+安全 | 保持外置规则兜底；v6 可选加 REFUSE 通道 | 中 |
| 5 | 长态势抽取失败 | 数据分布 | G7 已证 120 条可修（代价 -17pp basic）→ 云端压缩仍是首选架构 | 已闭合（P0-3） |
| 6 | 档位选择被 z 硬币掩盖 | 评测 | 修复 #1 后重跑五档矩阵再定部署档 | 中 |

**对 10 月任务书问题域的回答**：schema valid ≠ semantic correct 的实例 = 发现五（schema 合法但 mode 串槽）；"为什么位数更高不保证更准"的实例 = 发现二（z 低边际翻转）；量化误差"放大既有弱点而非创造新模式"的实例 = 发现一/二/五（全部失败模式在 Q8 上已存在，低位档只提高频率）。
