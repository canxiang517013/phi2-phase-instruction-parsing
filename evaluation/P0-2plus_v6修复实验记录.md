# v6 z 去指纹修复实验记录（P0-2 深度分析处方 #1 的实施与检验）

日期：2026-10-12/13　|　执行：舒毓川（ZCode 辅助）
任务依据：P0-2 深度分析修复清单 #1（z 参数化/扰动增强 + RECONFIGURE 数值自由度，"决定 phase 上限"）

## 1. 假设

H1：v5 的 z 是相位指纹（ASSEMBLE=5/OBST·RECON=15/RECONFIGURE=8 固定默认），模型推断 z 实质是推断相位身份；
H2：通过训练数据增强（显式 z 指令样本 + RECONFIGURE 默认加量 + z 边际再平衡），可以把 z 从身份载荷中剥离，
    从而提高 phase 准确率（特别是 RECONFIGURE 的 0/40 与 ASSEMBLE/RECON 的窜扰）。

## 2. 实验设计

- 冻结测试集不变（basic_240/phase_200/robust_600 项，隔离校验零泄漏含 v6 数据）
- 训练：v5 330 条 + 增强 155-180 条（种子 20261012/20261013，生成命令全文存 §7），QLoRA 400 步
  max_length=256（复用 v6lc 训练协议，运行时改参命令见 §7）
- 评测：五档中取 FP16/Q8_0/Q4_K_M 三档 × 三集（eval_run_v2，固定采样 seed=20260906）
- 对照：v5 同档（run2 固定 seed 版）

迭代：v6.1（180 条增强，全部 swarm）→ 发现 mode 偏置 → v6.2（155 条增强，55 条单机样本）。

## 3. 结果：v6.1（mode 偏置版，已归档不删除）

| 集 | v5-FP16 | v6.1-FP16 | 结论 |
|---|---|---|---|
| basic | 100% | **62.1%** | 90/91 失败全是 mode：单机条目全被输出 swarm（target/ids 全对） |
| phase | 52.5% | 55.0% | 背着 mode 偏置仍略升 |
| robust | 13.8% | — | （偏置版仅作诊断） |

**失败一记录**：增强样本 100% 硬编码 mode=swarm，挤掉 single-agent 类先验——深度分析"发现五（mode 冗余字段脆弱性）"
的活体演示。修复=v6.2 加入 1/3 单机样本。

## 4. 结果：v6.2（mode 平衡版）——失败，如实记录

训练正常收敛（最终 loss 0.354，与 v6.1 一致），但**推理级完全退化**：GGUF 模型对任何提示只输出单个换行
即停（无 stop 序列、40 token 上限下同样如此）；FP16 档评测表现为超长复读（GPU 100% 但 15 分钟零条目推进），
评测链被终止，无有效结果文件。

**排查过程**：训练损失曲线正常排除训练崩坏；merge/convert/quantize 各步骤日志正常；直连 llama.cpp 单条
测试确认输出退化。**已定位的数据缺陷**：生成器 bug 导致 16/155 条单机样本"指令机号 ≠ uav_ids"
（`single()` 在同一行内被多次调用取了不同值——3.3% 脏监督）。**未定位部分**：3% 脏监督按常理不足以
解释全局立即 EOS，深层根因待查（候选：增强样本措辞模板与 v5 分布的系统性冲突导致输出先验坍缩；
需对照实验分离数据缺陷与训练随机性两个因素）。

**根因判断（当前假设，置信度中）**：数据缺陷 + 训练敏感性的复合作用；v6.1 同管线同脚本成功，唯一差异
是数据内容，指向数据侧。**后续验证**：v6.3 = 修复机号 bug + 补默认值样本（每条显式 z 样本配一条同相位
默认 z 样本，对抗发现 B 的稀释效应），若仍退化则排除数据因素转查训练脚本稳定性。

## 4b. v6.1 完整结果（三档，作为 v6 实验的有效数据；均背着 mode 偏置）

| 集 | v5 FP16/Q8/Q4 | v6.1 FP16/Q8/Q4 |
|---|---|---|
| basic | 100 / 100 / 97.9 | 62.1 / 61.3 / 62.1（mode 偏置：90 条单机全灭，其余全对） |
| phase | 52.5 / 57.5 / 41.5 | 55.0 / 50.0 / **64.5** |
| robust | 13.8 / 13.8 / 9.4 | 16.2 / 16.9 / 17.5 |

**亮点（Q4 悬崖消失）**：v6.1-Q4 的 phase 64.5% 是迄今全部模型×档位测得的最高值（v5 全档最佳 58.0），
且 v5 的"Q4 相位悬崖"（41.5 vs Q8 57.5，p<0.0001）不复存在——精确印证深度分析发现二的预测
"z 边际硬币翻转是悬崖主因，z 修复后档位排序可能重排"。robust 三档也全面提升（+2.4~+8.1pp）。
若 v6.3 修好 mode 偏置而保持 z 效果，phase 预计还能再上一层（mode 偏置在 phase 集同样压分）。

## 5. 逐相位 z 解剖（关键科学发现，v6.1/v6.2 合并解读）

| 相位(期望z) | v5 正确/z 塌向 | v6 增强后 | 判读 |
|---|---|---|---|
| ASSEMBLE(5) | 23-29/40，窜 15 | **27-32/40，z=5 更集中** | 增强有效 |
| HOLD(自由) | 40/40 | 40/40 | 不受影响 |
| OBSTACLE(15) | 20-21/40，散布 8/17/22 | z=15 大幅集中（21→32）但正确数持平 | 分布修复≠语义修复（散布错误换成集中错误） |
| RECON(15) | 16-31/40，窜 5 | FP16 16→18，**Q8 31→14 恶化** | 显式 z 样本稀释了默认值映射 |
| RECONFIGURE(8) | 0/40，塌 15 | **仍 0/40，塌向迁移为 5** | 殖民未消除只换了宿主 |

**发现 A（殖民迁移）**：z 边际再平衡（z=8 从 57→97 居首）没有消除 RECONFIGURE 塌缩，塌向从 15 换成 5——
众数吸引子由"频率最高值"变为"最简默认值"，说明 z 的身份推断机制仍在起作用，只是换了判据。
**发现 B（默认-覆盖二难）**：教"指令显式 z 优先"（H2 的覆盖泛化半边）会稀释"无 z 指令→相位默认"（记忆半边），
RECON 在 Q8 上净恶化即其证据。数据层增强无法同时最优化两者。

## 6. 结论与处方修订

1. **H2 部分成立**：ASSEMBLE 与 OBSTACLE 的 z 分布显著改善；但 RECONFIGURE 上限未动（仍 0/40）。
2. **处方修订**：z 的身份载荷问题在数据层不可完全修复，治本方案是**相位语法层参数化**
   （处方 #1 的另一半：如 `RECONFIGURE@line@(15,15,8)`，让相位串直接携带 z，模型不再需要记忆默认值）——
   但该改动会使冻结测试集的相位契约失效，须与测试集 v2（相位参数化版）同步演进，列为 v7 工作。
3. **mode 冗余的实证**（发现五升级）：180 条单类增强即令 mode 全盘翻车，确认"删 mode/由 ids 推导"的必要性
   （同样需测试集 v2 配合）。
4. 对论文的意义：本实验是"数据修复 vs 结构修复"边界的受控证据——量化了训练数据增强的能力边界，
   支持论文的系统层叙事（语法压缩 + 外置安全层优于端侧记忆修补）。
