## 三、失败与异常记录

### 异常一：PX4 局部坐标导致追击目标无效

**现象**：相位 `INTERCEPT@(-0,-0,10)` → 无人机起飞后原地上升 10 米→悬停→降落（"盘旋一圈"）。
**排查**：红队节点日志显示 `ned: [0.0, 0.0, 0.0]`，蓝队质心被计算为 (0,0)。
**根因**：PX4 `VehicleLocalPosition` 是相对各机起飞点的**局部坐标**——所有无人机地面时都报 [0,0,0]，与 AirSim 世界坐标无关。相位生成器直接用局部坐标算蓝队质心，永远是 (0,0)。
**修复**：加入 `DRONE_WORLD_OFFSETS`（与 AirSim settings.json 的 X/Y 对应），将局部 ENU 加偏移转为世界坐标。修复后相位正确变为 `PURSUE@(52,50)`。
**教训**：跨仿真器坐标转换是常见陷阱，应在架构设计阶段明确坐标契约。

### 异常二：架构重构后 import 路径丢失

**现象**：`ModuleNotFoundError: No module named 'phase_rules'`
**根因**：从 Windows 复制更新后的源文件到 WSL2 时，覆盖了之前的 import 路径修正（`from ..common.phase_rules import`）。
**修复**：Windows 侧源码直接改为正确的包内相对导入，部署脚本加 sed 保障。

### 异常三：裁判秒判红胜（已修复，上周遗留）

**现象**：启动后裁判立即判定 `red_wins (capture at 0.0m)`
**根因**：PX4 未连接 AirSim 时四机全报 [0,0,0] → 距离 = 0 < 15m → 立即红胜
**修复**：蓝队位置有效性检查（须在 (50,50) 附近）+ 10 秒宽限期 + 起飞前间距校验

**建议**：先在 2v2 上完成完整实验，论文中说明扩展性（架构已支持 N 机）。
