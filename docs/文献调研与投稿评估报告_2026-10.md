## 1. 完整研究框架（师兄基座 → 本项目拓展）

### 1.1 架构总图

```
═══════════ 训练层（师兄已发表工作：phase-aware-llm-meta-controller）═══════════
  2D 移动长机编队环境（MAPPO/CTDE，14 维 obs / 22 维 global state）
      ↓ 训练指标流（编队获取率 / 跟踪误差 / 成功率）
  单调相位检测 Early→Mid→Late（指标阈值 + patience 驱动）
      ↓ 相位条件化 LLM 咨询（间隔 30/50/100 ep + 性能退化触发）
  LLM 元控制器（deepseek-r1:14b@Ollama，temperature=0）
      ↓ 语义建议三元组：参数 × 方向 × 幅度
  六层确定性安全层：白名单→数量上限→乘法换算→边界 clip→相位平滑→最小有效变化
      ↓ 有界参数更新（w_position / w_formation / w_success / entropy_coef）
  下一训练周期   ‖ 评测：10 预注册 seed × Wilcoxon/Holm/bootstrap 配对统计
═════════════════════════╤════════════════════════════════
                          │ 公共原语：相位信号（phase）
═════════════════════════╧════════════════════════════════
═══════════ 部署层（本项目拓展，证据链已基本建成）═══════════
  云端：态势文本 → 规则引擎 → 10-token 相位串（ASSEMBLE@… / HOLD@… / …）
      ↓ 受限信道（延迟 / 丢包 / 断连 / 旧消息重放，故障注入可插拔）
  PhaseLink 状态机：timestamp + TTL 2s + 退化时限 3s → 相位无关安全悬停
      ↓ 新鲜相位 + 用户自然语言指令
  端侧 SLM：Phi-2 2.7B QLoRA，相位条件化指令解析（JSON 动作原语）
      ↓ 五档量化（FP16/Q8/Q6/Q5/Q4）× 能力维度部署边界
  SafetyLayer：schema / 包络 / 分轴数值溯源 / 相位一致性 → hold 安全默认
      ↓ 动作原语 → PX4 Offboard（双机闭环）
══════════════════════════════════════════════════════════
```

### 1.2 两层学术分工

| 维度 | 师兄（基座） | 本项目（拓展） |
|---|---|---|
| phase 的角色 | 训练调度信号（离线、episodic、无带宽约束） | 运行时通信协议（10-token 云-边语义瓶颈） |
| LLM 的位置 | 训练环外咨询（每 30-100 ep） | 执行环内解析（每指令一次，延迟敏感） |
| 安全层形态 | 参数域（白名单/clip/平滑） | 动作域（schema/包络/数值溯源/TTL） |
| 受限性叙事 | 训练预算（episodes） | 算力（量化）+ 通信（延迟/断连）双重受限 |
| 评测重心 | 收敛速度/最终性能配对统计 | 能力维度×量化档位边界 + 因果消融 + 鲁棒性 |

**论文一句话定位**：把"相位感知的 LLM 元控制"从训练时推进到运行时——phase 从调度信号升格为受限云-边链路上的语义瓶颈协议，并给出其压缩收益、量化边界与断连鲁棒性的因果证据。师兄的确定性关卡约束 LLM 思想在动作域安全层中得到同构延续——"拓展"而非"并列"。

### 1.3 需要前置澄清的接口问题（写作红线之一）

两层 phase 是否同一概念：师兄的 phase 是**训练进度三段**（early/mid/late，单调），本项目的 phase 是**任务态势语法**（ASSEMBLE/HOLD/RECONFIGURE/OBSTACLE_AVOID/RECON，带参数）。论文需一小节 + 一张映射图形式化两者关系（建议表述：部署 phase 的类别空间 ⊇ 训练 phase 的单调映射；运行时相位序列的统计量可作为训练层元控制器的输入——接口预留已写入 `docs/P0-4_接口定义与实施计划.md` §4）。

## 2. 项目信息与假设

- 领域：多无人机集群的 LLM/MARL 分层协同控制（延续师兄方向）
- 研究问题：算力与通信双重受限下，相位信号作为云-边语义瓶颈能否以更低成本保持任务性能，并在延迟/断连下更鲁棒
- 核心方法：10-token 相位语法 + Phi-2 QLoRA 相位条件化解析 + 确定性安全层 + TTL 链路
- 已有结果：600 条冻结评测（隔离零泄漏）、G1-G7 因果消融、五档量化边界、安全层危险拦截 100%、TTL 五场景 pilot、师兄仓库 43 run 复现（机制级吻合：白名单拒绝率 72% 与论文精确一致）
- 目标：2027-04 投稿，免费订阅制 SCIE（导师意见），首选 AST 梯队

**假设（未确认项，确认后修订本文档）**：① 师兄论文 venue 与时间（假设早于本项目 6 个月+，可"builds on"）；② 本项目论文为纯部署层 + 接口预留（不重做训练层实验）；③ 相位语法允许 v7 参数化扩展并作为贡献；④ phase 概念署名边界无限制；⑤ 算力 = 本机 6GB + 借用大显存机器。

## 5. 重点论文结论（写作用）

### 5.1 三条写作红线（不能写首创）

1. **端侧小模型指令解析**——LMUCS[3] 已做（0.5B Q4 Jetson 实机 + 8 模型横评 + 38k 开源数据集）。只能写"相位条件化的端侧解析"并引用对比。
2. **LLM 外置确定性安全层**——PKEG[2] 四层校验已是卖点；[13][14] 通用护栏方向亦活跃。本项目安全层只作系统组件，可主张的差异化子点 = **分轴数值溯源**（输出数值必须来自指令/相位上下文）+ 与 TTL 链路联动。
3. **"陈旧消息比不通信更有害"**——CAIC[4] 已实证。TTL 表述改为"云-边指令链路的协议化应对"。

### 5.2 训练层拥挤的证据（拓展叙事的动机）

[17][18] 表明 2026 年"LLM 调 RL 超参/奖励"已进入拥挤期（population-based、scaffolding 均已发表）→ 师兄工作的独特性在"相位条件化 + 确定性安全层"而非 LLM 调参本身；本项目转向运行时/受限云-边恰好避开拥挤区，且训练层元控制确实不解决部署时的算力/通信约束。

### 5.3 对标工作量拆解（推断，依据全文阅读）
