# 02 · 项目命名与目录规范

> 适用范围：`/home/abc/桌面/syc/` 仓库根及全部子域。本文档是 3v3 对抗项目的**强制基线**，新代码不合规范不合并；存量代码在重构中逐步对齐（见《04_重构执行计划》）。

---

## 1. 顶层目录标准

```
syc/                        ← 仓库根（实验室工作区，不更名）
├── AGENTS.md               ← 实验室规则（保留原位）
├── README.md               ← 项目总览 + 快速上手（新人入口）
├── .gitignore              ← 版本控制排除规则
├── docs/                   ← 全项目文档（编号命名，见 §6）
├── configs/                ← 【部署域】对抗部署顶层配置（红蓝阵容/机型/场景）
│   ├── robots/             ←   机型档案（异构硬件参数化）
│   ├── formations/         ←   红蓝阵容编排（哪个机位用哪个机型+角色）
│   └── scenarios/          ←   对抗场景（地图/初始条件/胜负规则）
├── llm/                    ← 【训练域】LLM 指令解析训练全流程
│   ├── configs/            ←   训练域内部配置（数据版本/超参/路径集中）
│   ├── datasets/           ←   训练集（冻结，版本化命名）
│   ├── testsets/           ←   冻结测试集（只读！）
│   ├── phi2_common/        ←   共享库正式包（phase_rules/phase_link/safety_layer）
│   ├── train/  merge/  eval/  benchmarks/   ← 主链路脚本按阶段分层
│   ├── adapters/           ←   LoRA 权重产物（版本化命名）
│   ├── models/             ←   基座模型（大文件，gitignore）
│   ├── runs/               ←   每次训练的日志/checkpoint（按日期+标签）
│   ├── scripts/            ←   环境工具（下载/校验/加速）
│   └── tests/              ←   训练域单元测试
├── ros2_ws/                ← 【部署域】ROS2 工作区（待迁移，见《03》）
│   └── src/
│       ├── uav_common/         ← 通用库（消息/坐标变换/日志）
│       ├── uav_single/         ← 单机逻辑（DMPC 控制、单机状态机）
│       ├── strategy_common/    ← 对抗策略基类（红蓝共享的抽象）
│       ├── strategy_red/       ← 红方策略（禁止 import strategy_blue）
│       ├── strategy_blue/      ← 蓝方策略（禁止 import strategy_red）
│       ├── sim_interface/      ← 仿真接口（AirSim/Gazebo 桥）
│       └── referee/            ← 裁判系统（不依赖任何策略包）
└── archive/                ← 历史归档（迁移包原件等，只进不改）
```

**规则：**
- 生成物（日志/checkpoint/权重/tar 包）**永不**与源码平级；源码目录里只放源码。
- 域内配置（`llm/configs/`）管训练；顶层 `configs/` 只管对抗部署。两层不混用。
- `archive/` 只增不改；进入条件：确认再无直接引用。

## 2. ROS 2 命名规则（遵循 ROS 社区最佳实践）

### 2.1 包名

| 规则 | 示例 |
|---|---|
| 全小写 snake_case，`<域>_<职责>` 两段式 | `uav_common`、`sim_interface` |
| 禁止大写、连字符、中文 | ❌ `UAV-Common`、❌ `裁判系统` |
| 红蓝以包为边界，物理隔离代码 | `strategy_red` / `strategy_blue` |
| 单数职责命名，避免 mega-package | ❌ `everything` |

### 2.2 节点名

- 格式：`<职责>_node`，小写 snake_case。
- 节点**必须**运行在命名空间下，全局唯一名 = `/<team>/<uav_id>/<职责>_node`。
- 示例：`/red/uav1/llm_parser_node`、`/red/uav1/dmpc_controller_node`、`/blue/uav3/vision_node`、`/referee/score_node`（裁判无 team 前缀，直接挂 `/referee`）。

### 2.3 话题名

- 小写 snake_case，名词或 `名词_名词`；动词留给服务。
- 层次 = 命名空间自动前缀，**话题名本身不重复携带 team/uav 信息**：
  - 单机内：`cmd_vel`、`odom`、`battery`、`target_pose` → 实际 `/red/uav1/cmd_vel`
  - 队伍级广播（挂在 `/<team>` 命名空间）：`formation_cmd`、`team_status`、`enemy_sightings`
  - 裁判级（挂 `/referee`）：`score`、`match_state`、`penalty_events`
- 保留名不动：`tf`、`tf_static`、`parameter_events`、`rosout`。

### 2.4 服务名 / 动作名

- 服务：**动词或动词短语开头**。`arm`、`takeoff`、`land`、`set_formation`；裁判：`/referee/start_match`、`/referee/pause_match`、`/referee/judge_hit`。
- 动作（长任务）：`动词_名词`。`navigate_goal`、`engage_target`、`return_home`。

### 2.5 参数名

小写 snake_case，语义自明：`team_color`、`uav_id`、`model_path`、`lora_adapter_version`、`safety_strict_mode`。禁止拼音缩写。

### 2.6 消息/服务定义（`uav_common` 内）

- 文件 PascalCase：`FormationCommand.msg`、`EnemySighting.msg`、`StartMatch.srv`。
- 字段 snake_case：`target_position`、`confidence`。
- 红蓝通用消息定义**只允许**放在 `uav_common`；裁判协议放 `referee/msg|srv`。

### 2.7 Launch 文件

- `<目的>.launch.py`：`red_full.launch.py`、`blue_full.launch.py`、`referee.launch.py`、`sim_3v3.launch.py`、`llm_parser_standalone.launch.py`。
- 每个 launch 必须支持 `team`、`uav_id` 参数并推入命名空间。

## 3. Python 命名规则

| 对象 | 规则 | 示例 |
|---|---|---|
| 模块/文件 | snake_case | `phase_rules.py`、`safety_layer.py` |
| 类 | PascalCase | `SafetyLayer`、`PhaseLink` |
| 函数/方法 | snake_case，动词开头 | `validate_phase()`、`merge_adapter()` |
| 常量 | UPPER_SNAKE | `DEFAULT_PHASE`、`MAX_ALTITUDE_M` |
| 包 | snake_case 单数 | `phi2_common` |

## 4. 文件名 ↔ 类名映射规则

| 文件类型 | 文件名模式 | 类名模式 | 示例 |
|---|---|---|---|
| ROS 节点 | `<职责>_node.py` | `<职责首大写>Node` | `llm_parser_node.py` → `LLMParserNode` |
| 库模块 | `<模块名>.py` | `<模块首大写><职责>` 或主类同名 | `safety_layer.py` → `SafetyLayer` |
| 工具脚本 | `<动词>_<宾语>.py`，可执行、无类或仅 main | — | `download_model.py`、`merge_adapter.py` |
| 生成器 | `gen_<产物>.py` | — | `gen_testset.py` |
| 测试 | `test_<被测模块>.py` | — | `test_safety_layer.py` |

## 5. 版本化资产命名（数据集/权重/运行记录）

| 资产 | 模式 | 示例 |
|---|---|---|
| 训练集 | `dataset_<任务>_<版本>.jsonl` | `dataset_dmpc_v5.jsonl`、`dataset_dmpc_v6lc.jsonl` |
| LoRA 权重目录 | `adapters/<任务>_<版本>[_<来源>]/` | `adapters/dmpc_v5/`（本机产出）、`adapters/dmpc_v5_original/`（原机器权威件） |
| 合并模型 | `merged_<任务>_<版本>/` | `merged_dmpc_v5/` |
| GGUF | `<任务>_<版本>_<量化档>.gguf` | `dmpc_v5_q5_k_m.gguf` |
| 运行记录 | `runs/YYYYMMDD_<版本>_<标签>/` | `runs/20261015_v5_4090_baseline/` |

- 版本号小写 `v<数字>[<小写变体>]`；**版本里禁止硬件名**（硬件属于 run 标签，不属于模型版本）。
- `_original` 后缀 = 外部迁移的权威原件，只读。

## 6. 文档与配置文件命名

- 文档：`docs/NN_<主题>.md` 两位编号排序（本文档系列即示例）；中文标题允许，文件名用可排序短拼音/英文主题。
- 配置：`<域>_<目的>.yaml`（`train_dmpc_v5.yaml`、`red_lineup.yaml`、`scenario_3v3_valley.yaml`）；YAML 键 snake_case。
- 禁止：`final`、`new`、`backup`、`副本`、日期后缀出现在**源码/配置**文件名中（日期只允许出现在 `runs/` 与日志）。

## 7. Red / Blue / Referee 边界强制规则

1. `strategy_red` 与 `strategy_blue` **互不 import**；共享逻辑上提到 `strategy_common`。
2. `referee` 不 import 任何 `strategy_*` / `uav_single`；只通过 `uav_common` 消息与 `/referee` 话题服务交互。
3. 红蓝差异（模型权重、参数、策略常量）全部落在 `configs/formations/`，**代码里不写死队伍身份**。
4. CI/审查检查点：任何 PR 触碰对方策略包或裁判包依赖方向反转即拒绝。
