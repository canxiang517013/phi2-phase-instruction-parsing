# 03 · 目标架构设计（3v3 对抗）

> 设计输入：《01》问题清单 P9、《02》命名规范、迁移指南中的上游论文（Phase-Aware LLM Meta-Controller）。
> 核心思路：**训练域与部署域物理分离，LLM 是两域之间的交付物**。

---

## 1. 双域一图

```
┌─────────────────────── 训练域 llm/ ───────────────────────┐
│  datasets ──> train ──> adapters/dmpc_vN ──> merge ──> GGUF│
│  testsets ──> eval（六指标/矩阵/隔离/稳定性）                │
│  phi2_common（phase_rules / phase_link / safety_layer）    │
└──────────────────────────┬────────────────────────────────┘
                           │ 交付物：adapter/GGUF + safety_layer（代码级复用）
┌──────────────────────────┴────────────────────────────────┐
│                      部署域 ros2_ws/                        │
│                                                            │
│  /referee（裁判）    /red（红方 3 机）      /blue（蓝方 3 机）│
│   referee ──────┐    strategy_red            strategy_blue │
│  start_match    │    └─ llm_parser_node       └─ llm_parser │
│  judge_hit      │       φ = phi2+adapter         (同构复用)  │
│  score/m_state  │       ↓ phi2_common.safety_layer           │
└────────┬────────┘    formation_cmd（队伍级）                  │
         │                ↓                                     │
         │          uav_single（每机：dmpc_controller 等）        │
         │                ↓ cmd_vel/attitude                    │
         │          sim_interface（AirSim/Gazebo 桥）            │
         │                ↓                                     │
         └──────────  仿真环境（唯一物理真相源）                   │
                                                            │
│  共享底座：uav_common（消息定义/坐标/日志） + strategy_common   │
└────────────────────────────────────────────────────────────┘
```

关键设计判断：
- **LLM 解析器是策略的子组件，不是独立队伍**：`llm_parser_node` 由 `strategy_*` 包提供 launch，运行在 `/<team>` 命名空间下，加载 `configs/formations/` 指定的 adapter 版本——红蓝可用不同权重。
- **`safety_layer` 双域复用**：训练域评测与部署域运行时用**同一份代码**（`llm/phi2_common/safety_layer.py`），ROS 侧以路径引用或轻量 vendor 引入，保证"训练时验证过的拦截 = 部署时生效的拦截"。
- **裁判是第三方**：独立包、独立命名空间、不依赖策略代码，只认 `uav_common` 协议——保证对抗公平性与可重放。

## 3. 模块职责边界表

| 模块 | 职责 | 允许依赖 | 禁止 |
|---|---|---|---|
| `uav_common` | 消息定义、坐标系约定、日志规范 | 仅 ROS2 核心库 | 依赖任何业务包 |
| `uav_single` | 单机 DMPC、状态机、执行指令 | `uav_common` | 知道红蓝、知道裁判、知道其他机 |
| `strategy_common` | 策略基类、威胁评估等共享抽象 | `uav_common` | 含任何队伍专属常量 |
| `strategy_red/blue` | 队伍级决策、LLM 指令解析节点、编队指挥 | `uav_common`、`strategy_common`、`llm/phi2_common`（vendor） | 互依；触碰裁判协议写方 |
| `sim_interface` | 仿真环境读写桥接、物理真相分发 | `uav_common` | 含策略逻辑 |
| `referee` | 计分、比赛状态机、判罚、重放记录 | 仅 `uav_common` 协议 | 依赖 `strategy_*`/`uav_single` |
| `llm`（训练域） | 数据、训练、评测、权重产出 | —（独立 conda 环境） | 运行时反向依赖 ros2_ws |

## 4. 多机异构配置模式

三层配置解耦"机型—阵容—场景"：

1. **机型档案** `configs/robots/<platform>_<role>.yaml`：质量/最大速度/载荷/传感器清单等物理参数，与队伍无关。
2. **阵容编排** `configs/formations/<team>_lineup.yaml`：声明 3 个机位各自引用的机型档案 + 角色权重 + **LLM adapter 版本**（红蓝可用不同权重/量化档）。
3. **场景** `configs/scenarios/*.yaml`：地图、初始位置、胜负条件、时长；红蓝共用一份，保证公平。

launch 链：`ros2 launch strategy_red red_full.launch.py lineup:=red_lineup.yaml` → 逐机起节点并注入 `/red/uavN` 命名空间与机型参数。新增异构机型 = 只加一个 robot 档案 + 改 lineup，**零代码改动**。

## 5. 运行时数据流（LLM 在环位置）

```
操作员/剧本 ──自然语言──> /red/llm_parser_node（phi2 + adapter + safety_layer）
                              │ 结构化 FormationCommand（JSON→msg）
                              ▼
                     /red/formation_cmd ──> strategy_red 决策节点
                              │ 分解为单机目标
                              ▼
                     /red/uav{1..3}/target_pose ──> uav_single DMPC
                              │
                              ▼
                     /red/uav{1..3}/cmd_vel ──> sim_interface ──> 仿真环境
                              │                              │
                              └──── /referee/judge_hit ◄──────┘（碰撞/命中事件由裁判裁定）
```

安全层职责链：LLM 原始输出 → `safety_layer`（五层确定性拦截，与训练评测同源） → 才允许进入策略。**任何未经 safety_layer 的 LLM 输出直接进控制链路 = 架构违规。**

## 6. 训练域内部治理要点

- 路径集中：所有脚本从 `llm/configs/paths.py` 取 `BASE_MODEL`、`DATASET(ver)`、`ADAPTER(ver)`，消灭 13 处硬编码（问题 P4）。
- 正式包化：`phi2_common` 带 `__init__.py`，评测/安全/链路脚本改为 `from phi2_common.phase_rules import ...`，删除全部 `sys.path.insert` hack（问题 P3）。
- 冻结资产只读标记：`testsets/`、`adapters/*_original/`、`datasets/`（文档层面冻结 + 后续可加 hash 校验脚本）。
