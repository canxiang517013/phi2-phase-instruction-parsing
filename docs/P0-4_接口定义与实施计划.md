# P0-4 接口定义与实施计划（SLM+MAPPO 双机闭环）

日期：2026-10-12　|　状态：离线部分已启动（安全层 + 通信链路），双机部分待排期

## 1. 接口选型（任务书要求：只保留一种清晰接口）

**SLM 输出角色 = 动作原语（action primitive），不采用 subgoal、不采用 phase-conditioned 参数。**

理由：
- 8 月双机链路已验证的就是"解析→JSON 动作→PX4 Offboard"，沿用最小改动；
- P0-2/P0-3 证明 SLM 的能力边界恰好在"结构化短输出"（G4 标签 55% vs 散文 0%），动作原语是最短输出；
- phase-conditioned 参数（师兄路线）在训练层，与端侧部署层解耦，不混用。

## 2. 数据流与关卡（三层防线）

```
云端 cloud_phase_generator
  └─ /phase_signal（10 token 相位串 + 发送端时间戳）
       └─ phase_fault_proxy（P1 故障注入，实验时才插入）
            └─ PhaseLink（scripts/phase_link.py，端侧内嵌）
                 · TTL 2 s 拒旧、退化时限 3 s、退化→安全悬停、恢复重对齐
                 · 输出：新鲜相位 | 安全悬停决策
       ┌─ 新鲜相位 + 用户指令
       ▼
端侧 SLM（Phi-2 v5，llama.cpp）
  └─ 原始 JSON 输出
       ▼
SafetyLayer（safety/safety_layer.py，P0-4 强制关卡）
  · JSON schema（mode/formation/ids/target 类型与取值域）
  · 数值包络（|x|,|y|<=300，0<=z<=60，ids 含于 {1..5}）
  · 数值溯源（输出数值必须来自指令/相位上下文或分轴契约常量——
    拦截众数捏造与歧义捏造；分轴：x 无常量、y 仅 0、z 可 5/15）
  · 相位-动作一致性（RECONFIGURE 阵型匹配 / 移动相位目标匹配）
  · 拒绝 → SAFE_DEFAULT（hold 悬停，与断连降级同语义）
       ▼
动作原语 → PX4 Offboard（双机）；MAPPO 侧预留订阅接口（见 §4）
```

## 4. MAPPO 对接预留（师兄仓库接口）

- 订阅：`/phase_signal`（云端相位，训练层元控制器可用同一信号驱动 phase-aware 调参，与本部署层只读不冲突）
- 预留：动作原语流 `/action_primitives`（JSON，schema 同 SafetyLayer 输出）供 MAPPO 作为外部指令边界条件（如任务切换事件），不直接进 PPO 动作空间
- 依据：P0-1 复现确认师兄 MAPPO 是训练层元控制，部署层闭环以 PX4 为终点；两者通过 phase 信号与任务事件解耦

## 5. 双机实施步骤（待执行，复用 8 月 px4_ws 环境）

1. WSL2 起 llama.cpp server（`启动指令` 文件中的命令）+ nl_command_node（内嵌 PhaseLink 与 SafetyLayer）
2. Windows/AirSim 侧双 PX4 实例 + cloud_phase_generator
3. 场景脚本：正常指令 / 越界指令 / 断连 10 s / 旧相位重放 四场景各 3 次
4. 验收：完整 episode 保存 phase 消息、SLM 原始输出、安全层裁决、PX4 状态、reward（若有）、通信时间戳；越界/断连场景零危险动作
5. 产物：日志 + 视频 + 配置 + 可复现命令，入 `evaluation/P0-4/`

## 6. 风险与边界

- SafetyLayer 数值溯源的上下文 =（指令 + 相位串）；若未来端侧需要态势缓存数字，白名单相应扩展并复跑语料验证
- z 近默认抖动（z=4 vs 5）的 1-2% 误拦：可接受（拒绝→悬停无损安全），不改契约
- 长上下文场景的"抄态势大数"安全层不拦（数值可溯源）——上游用 G4 相位压缩解决，已在 P0-3 定量
